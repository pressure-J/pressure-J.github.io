1. Python 内置 int（90% 的题只用它就够）

1.1 模幂：必须用三参 pow

pow(base, exp, mod)        # 模幂，O(log exp)
pow(3, 100, 7)             # 4

为什么一定要用它：(3**100) % 7 是先把 3^100 这个天文数字完整算出来再取模。实测：

写法 耗时（10^6 量级指数）
(3**e) % 7 0.12 s
pow(3, e, 7) 0.000008 s

快 15000 倍，而且指数一大直接卡死。RSA 里 pow(c, d, n) 是全流程的性能命脉。

1.2 模逆（Python 3.8+ 内置，不用再手写扩展欧几里得）

pow(a, -1, m)      # 求 a 在模 m 下的逆元
pow(3, -1, 7)      # 5    （3*5=15≡1 mod 7）

不存在逆元时抛 ValueError，可以 try 当"gcd≠1"的判据。

1.3 大整数 ↔ 字节串（转 flag 全靠它）

n = 0x666c6167
n.to_bytes(4, 'big')              # b'flag'
b'flag'.hex()                     # '666c6167'
int.from_bytes(b'flag', 'big')    # 1718378855
int('666c6167', 16)               # 十六进制串转整数
hex(1718378855)                   # '0x666c6167'
  • 长度不足要指明：(65).to_bytes(4,'big') → b'\x00\x00\x00A'。只给 to_bytes(1) 会 OverflowError。
  • long_to_bytes（§2）比手写 to_bytes 更省心：它按最小字节数自动算长度，直接 .decode() 就是明文，不用自己数位数。

1.4 其它

import math
math.gcd(a, b)      # 最大公约数（RSA 共素数攻击的核心）
math.isqrt(n)       # 整数平方根（Rabin 开方第一步）
math.lcm(a, b)      # 最小公倍数

⚠️ 大数字符串转换限制（Python 3.11+）：实测本机 sys.get_int_max_str_digits() == 4300，超过就报错：

str(10**5000)   # ValueError: Exceeds the limit (4300 digits) for integer string conversion
int('9'*5000)   # 同样报错
hex(10**5000)   # 没事（十六进制不受限）

RSA 里要把超大整数打印/转十进制时先加一行：

import sys
sys.set_int_max_str_digits(100000)     # 提到 10 万位

注意：hex() 和 to_bytes() 不受此限，只有 str()/int(str) 十进制互转受限。

2. Crypto.Util.number（pycryptodome）—— RSA 题主力

from Crypto.Util.number import (
    getPrime,          # 生成 n 位随机素数
    getStrongPrime,    # 强素数（p-1 有大素因子），出题用
    isPrime,           # Miller-Rabin 素性判定
    inverse,           # 模逆，等价 pow(a,-1,m)
    GCD,               # 带大数加速的 gcd
    size,              # 一个数占多少 bit
    bytes_to_long,     # 字节串 → 整数   （明文 m 的还原方向）
    long_to_bytes,     # 整数 → 字节串   （出 flag 用这个）
    getRandomNBitInteger,
    getRandomRange,
)

实测：

getPrime(512)                          # 512 位随机素数
inverse(3, 11)                         # 4
long_to_bytes(0x666c6167)              # b'flag'
bytes_to_long(b'flag')                 # 1718378855
size(0xffff)                           # 16  （位长）
long_to_bytes(65, 4)                   # b'\x00\x00\x00A'  （强制 4 字节，定长场景用）
getRandomNBitInteger(32).bit_length()  # 32

用法要点
- long_to_bytes(m) 出来的就是明文字节流，末端常带 \x00 补齐的没有（它用最小长度），直接 .decode(errors='ignore') 看 flag。
- 反过来写脚本出题：bytes_to_long(b'flag{test}')。
- inverse 与 pow(a,-1,m) 等价，优先用内置 pow，少一个 import。

3. 对称加密：Crypto.Cipher（pycryptodome）

3.1 AES 五种模式的构造差异（IV 是必踩的坑）

from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad

key = b'0' * 16            # AES 密钥：16/24/32 字节

AES.new(key, AES.MODE_ECB)                     # ECB：不接受 IV
AES.new(key, AES.MODE_CBC, iv)                 # CBC：iv 必须 16 字节
AES.new(key, AES.MODE_OFB, iv)                 # OFB：同上
AES.new(key, AES.MODE_CTR, nonce=b'1'*8)       # CTR：nonce（8 字节）
AES.new(key, AES.MODE_GCM)                     # GCM：nonce 自动生成

c = AES.new(key, AES.MODE_CBC, iv)
ct = c.encrypt(pad(b'flag', 16))               # ★ 加密前必须 pad
pt = unpad(AES.new(key, AES.MODE_CBC, iv).decrypt(ct), 16)
  • ECB 不用 IV，CBC/OFB 必须传 IV，CTR 传 nonce=；漏了会 TypeError。
  • CTR 也可以传 counter=：AES.new(key, AES.MODE_CTR, counter=Counter.new(128))（from Crypto.Util import Counter；键名是 counter_len / initial_value / prefix / suffix / little_endian，不是 nbits）。
  • GCM 用另一套方法（不是 encrypt/decrypt）：
c = AES.new(key, AES.MODE_GCM)
ct, tag = c.encrypt_and_digest(b'hi')
d = AES.new(key, AES.MODE_GCM, nonce=c.nonce)     # 解密要复用同一个 nonce
d.decrypt_and_verify(ct, tag)                     # 实测 → b'hi'

3.2 ECB 判块重复（"看到 ECB 就该想到"的第一反应）

实测：同一明文块加密后密文块相同，这就是 ECB 的结构泄露与重排攻击入口。

ct = AES.new(b'0'*16, AES.MODE_ECB).encrypt(b'A'*32)
ct[:16] == ct[16:]        # True —— 两块明文相同 → 两块密文相同

3.3 填充：pad / unpad 与 PKCS7

pad(b'x', 16)             # b'x' + 15 个 '\x0f'  → 长度 16
pad(b'0'*16, 16)          # 恰好满块时**再补一整块** 0x10×16 → 长度 32
unpad(pad(b'x',16), 16)   # b'x'
  • 块长是 AES.block_size（16），.hex() 看一堆 0f0f0f... 就是 PKCS7 的尾巴。
  • 解密忘了 unpad → 明文尾部一串 \x04\x04\x04\x04。
  • CBC 的 padding oracle / 比特翻转攻击正是打 unpad 的报错反馈。

3.4 其它算法（一表）

调用 说明
DES.new(key, mode, iv) 8 字节块、8 字节 IV
DES3.new(key, mode, iv) key 必须 24 字节，全 0 之类退化 key 会报错（实测 ValueError: Triple DES key degenerates to single DES）

4. 非对称：Crypto.PublicKey.RSA + 加密/签名封装

4.1 密钥的生成 / 导入 / 导出 / 手工构造

from Crypto.PublicKey import RSA

k = RSA.generate(1024)            # ★ 实测 512 会报错：RSA modulus length must be >= 1024
k.n, k.e, k.d                     # 直接出参数
k.export_key()                    # PEM 私钥（b'-----BEGIN RSA PRIVATE KEY-----'）
k.export_key(format='DER')        # DER
k.publickey().export_key()        # PEM 公钥（-----BEGIN PUBLIC KEY-----）

k2 = RSA.import_key(pem_bytes_or_str)     # 读 PEM/DER，自动识别公钥/私钥

# 手工构造（CTF 里"已知 n,e"或"已知 p,q"时最常用）
RSA.construct((n, e))                     # 只有公钥，用于加密/验签
RSA.construct((n, e, d))                  # 私钥（无 p,q）→ 实测可解出 d 参与运算
RSA.construct((n, e, d, p, q))            # 完整 CRT 加速

p、q 是素数才走 CRT，否则 construct 会报错——题目给的是合数因子时别硬塞。

4.2 加解密 / 签名验签（协议题、证书题用得上）

from Crypto.Cipher import PKCS1_v1_5, PKCS1_OAEP
from Crypto.Signature import pkcs1_15, pss
from Crypto.Hash import SHA256

# 加密（公钥）/ 解密（私钥）；PKCS1_v1_5 解密第二参是 sentinel，失败时返回它
ct = PKCS1_v1_5.new(k.publickey()).encrypt(b'flag')
pt = PKCS1_v1_5.new(k).decrypt(ct, None)          # → b'flag'

# OAEP 更安全，接口对称
ct = PKCS1_OAEP.new(k.publickey()).encrypt(b'x')
PKCS1_OAEP.new(k).decrypt(ct)                     # → b'x'

# 签名
h = SHA256.new(b'msg')
sig = pkcs1_15.new(k).sign(h)
pkcs1_15.new(k.publickey()).verify(SHA256.new(b'msg'), sig)    # 通过 → 返回 None（不抛异常即成功）

注意 verify 成功返回 None 而不是 True，要用"没抛异常"判断；写 if verify(...) 永远为假。

4.3 哈希 / HMAC（Crypto.Hash）

from Crypto.Hash import MD5, SHA1, SHA256, SHA512, SHA3_256, HMAC
SHA256.new(b'abc').hexdigest()                    # ba7816bf...
HMAC.new(b'key', b'msg', SHA256).hexdigest()      # bf1a0c12...

用途：给 pkcs1_15/pss 喂对象；算 HMAC 校验。纯求摘要用标准库 hashlib 更快（§8）。

5. gmpy2 —— 大数加速 + 数论原语

import gmpy2

gmpy2.mpz(x)              # 转 gmp 类型（大数运算提速，与 int 可混算）
gmpy2.invert(a, m)        # 模逆
gmpy2.powmod(a, b, m)     # 模幂
gmpy2.iroot(n, k)         # k 次方根 → (root, exact)；低加密指数攻击用它开方
gmpy2.is_square(x)        # 是否完全平方
gmpy2.gcdext(a, b)        # 扩展欧几里得 → (g, s, t)
gmpy2.is_prime(n, k)      # Miller-Rabin（k 轮）
gmpy2.next_prime(n)       # 下一个素数
gmpy2.isqrt(x)            # 整数平方根（*快*）
gmpy2.digits(x, 16)       # 转字符串进制
gmpy2.f_mod(a, m) / c_mod # 取模（结果符号不同，CTF 一般用 c_mod 保正）

实测返回值：

gmpy2.invert(3, 11)          # mpz(4)
gmpy2.iroot(gmpy2.mpz(27), 3) # (mpz(3), True)   ← 第二项 True 表示"精确开方"
gmpy2.gcdext(30, 12)         # (mpz(6), mpz(1), mpz(-2))  → 6=30*1+12*(-2)
gmpy2.f_mod(-3, 5)           # mpz(2)
gmpy2.c_mod(-3, 5)           # mpz(-3)
gmpy2.isqrt(10)              # mpz(3)

提速有多少？实测（别信"mpz 万能快"这种说法）

场景 内置 int gmpy2 提速
1024 bit 模幂 ×300 2.08 s 0.23 s 9.2×
2048 bit 模幂 ×60 2.76 s 0.30 s 9.2×
5000 bit isqrt ×1000 0.026 s 0.003 s 9×
4096 bit 乘加循环 ×3000 0.0020 s 0.0019 s 1.06×
小模数（2^1024−1 之类特殊数）模幂 — — 1.0×

结论：大数模幂/开方用 gmpy2 收益明显（近 10 倍，暴力跑几小时变几分钟）；普通小循环里 mpz() 化几乎没用，不必强求。另外 pow(a,b,m) 本身已是 C 实现，gmpy2 不是靠"换成 C"，而是靠 GMP 的 Montgomery 乘法优化。

6.1 常用调用

6.2 ⚠️ crt 的参数顺序：先模数，后余数

crt([3, 5, 7], [2, 3, 2])      # (23, 105)   23 mod 3=2, mod 5=3, mod 7=2  ✓
crt([2, 3, 2], [3, 5, 7])      # (5, 6)      ← 传反了它不报错，照样给你一个"解"

签名是 crt(m_list, v_list)，模数在前。返回 (解, 模数乘积)。传反不报错但结果完全错——共模/广播攻击里 CRT 合并错了会一路错到开方才发现，很难查。

solve_congruence((2, 3), (3, 5))   # (8, 15)  形如 (余数, 模数)，与 crt 相反

6.3 ⚠️ discrete_log(n, a, b)：求的是 b^x ≡ a (mod n)

discrete_log(n, a, b)    # 解 b^x ≡ a (mod n)  → 返回 x

实测（n=7，底 3 的幂表：3^1=3, 3^2=2, 3^6=1）：

discrete_log(7, 2, 3)    # 2      ← base=3, target=2：3^2=2 ✓
discrete_log(7, 3, 6)    # ValueError: Log does not exist   ← 6 阶只有 2，覆盖不到 3
discrete_log(11, 2, 7)   # 3      ← 7^3 = 343 ≡ 2 (mod 11) ✓

记忆法：第二个参数是"想求对数的那个数"（target），第三个是"底"（base）。写反了要么报 Log does not exist，要么静默给错值。底若不是原根，超出阶的目标直接报错。

7. gmssl —— 国密 SM2 / SM3 / SM4

7.1 SM3

from gmssl import sm3, func
sm3.sm3_hash(func.bytes_to_list(b'abc'))
# '66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0'
sm3.sm3_hash([0x61, 0x62, 0x63])      # 等价，入参就是 list[int]
  • 入参是 list[int]，不是 bytes，所以到处都要 func.bytes_to_list(...)。返回值是 hex 字符串（不是 bytes）。
  • gmssl.func 里还有：list_to_bytes / pkcs7_padding / zero_padding / random_hex(n) / xor。
  • 标准库 hashlib 没有 SM3（实测 hasattr(hashlib,'sm3') == False），本机 SM3 三选一：gmssl、openssl dgst -sm3。

7.2 SM4

from gmssl import sm4
key = b'0123456789abcdef'          # 16 字节

c = sm4.CryptSM4(); c.set_key(key, sm4.SM4_ENCRYPT)
ct = c.crypt_ecb(b'0123456789abcdef')       # 16 字节明文 → **32 字节**密文（自动 PKCS7 填充）
d = sm4.CryptSM4(); d.set_key(key, sm4.SM4_DECRYPT)
d.crypt_ecb(ct)                             # → b'0123456789abcdef'  ✅ 往返

sm4.CryptSM4().set_key(key, sm4.SM4_ENCRYPT)
c.crypt_cbc(iv, data)                       # CBC：iv 在数据前面
  • 常量：SM4_ENCRYPT=0 / SM4_DECRYPT=1、PKCS7=0 / ZERO=1（实测取值）。
  • 默认带 PKCS7 填充，16 字节输入会变成 32 字节输出——别以为它没填充，解密侧要让它自己 unpad（crypt_ecb 解密已自动去填充，实测往返正常）。
  • 手动填充用 sm4.pkcs7_padding(list, block) / pkcs7_unpadding(...)。
  • OFB/CTR 它没实现，要自己用 sm4.SM4_BOXES_TABLE、one_round 之类的原语拼（见 ~/tools\CTF工具箱\crypto\22-SM2随机数缺陷与OFB密钥流重用.py）。

7.3 SM2

from gmssl import sm2, func
d   = '00'*31 + '01'                       # 私钥：64 位 hex 字符串（不是 bytes！）
pub = '...'                                # 公钥：128 位 hex，不带 04 前缀

# 没公钥时用私钥推（_kg 是内部方法，但实测可用）
kobj = sm2.CryptSM2(private_key=d, public_key='00')
pub  = kobj._kg(int(d, 16), sm2.default_ecc_table['g'])     # 返回 128 字符 hex

sm = sm2.CryptSM2(private_key=d, public_key=pub, mode=0, asn1=False)
ct = sm.encrypt(b'hello')          # → bytes，实测 len = 64 + len(msg) + 32 = 99
sm.decrypt(ct)                     # → b'hello' ✅（必须用相同 mode/asn1 的对象）

构造签名：CryptSM2(private_key, public_key, ecc_table=默认SM2曲线, mode=0, asn1=False)

参数 实测结论
mode 0 = C1‖C2‖C3，1 = C1‖C3‖C2。源码注释写"default is 1"，实际默认是 0——以实测为准。加密解密两侧必须一致，否则解出乱码
asn1 True 时密文外面包一层 DER 结构（OpenSSL 的密文格式）。asn1=False（默认）是裸拼接。两者互不兼容：拿 OpenSSL 的密文喂它要先看 asn1 标志
C1 长度 固定 64 字节（x‖y，无 04 前缀）
密文结构实测 mode=0：C1(64) ‖ C2(len(msg)) ‖ C3(32)；mode=1：C1(64) ‖ C3(32) ‖ C2，两者总长相同

签名（推荐带 SM3 的封装）：

sig = sm.sign_with_sm3(b'msg')           # 返回 128 位 hex 字符串（r‖s），内部自带随机 k
sm.verify_with_sm3(sig, b'msg')          # True / False（实测改一个字节就 False）
  • 要指定 k（复现随机数重用漏洞）用底层 sign(data, K)，K 是 hex 字符串——自己指定 k 就等于故意泄露私钥的场景。
  • 验签失败返回 False（不会抛异常），和 pycryptodome 的行为不同。
  • SM2 的 k 重用公式和 ECDSA 不一样：SM2 是 d = t/(1−t)，t = (s1−s2)/(r1−r2)（同一 k 下 r1=r2，s 相减）；照抄 ECDSA 的公式必得错私钥。详见 05-国密/SM2-椭圆曲线公钥算法原理与攻击.md。
  • gmssl 的 sm2.py 依赖 Cryptodome（pycryptodomex）；本机 Crypto 和 Cryptodome 都在，能正常用。若换机器只有 Crypto，import gmssl 会报 ModuleNotFoundError。

8. 标准库（任何环境都有，赛场兜底）

import hashlib, hmac, secrets, base64, binascii, struct

hashlib.sha256(b'abc').hexdigest()                     # ba7816bf...
hashlib.new('sha256', b'a').hexdigest()                # 动态算法名
hashlib.pbkdf2_hmac('sha256', b'pw', b'salt', 1000, 16) # 0a382535...
hashlib.scrypt(b'pw', salt=b'salt', n=2**14, r=8, p=1, dklen=16)

hmac.new(b'key', b'msg', hashlib.sha256).hexdigest()   # bf1a0c12...
hmac.compare_digest(b'a', b'a')                        # 抗时序比较，返回 True/False

secrets.token_bytes(16)      # 密码学安全随机 ★ 别用 random
secrets.randbelow(10)        # [0,10) 随机数

base64.b64encode(b'flag{x}')          # b'ZmxhZ3t4fQ=='
base64.urlsafe_b64encode(b'flag')     # URL 安全变体（+ / 换成 - _）
base64.b64decode('ZmxhZw==')          # 长度不对会 padding 报错 → 手动补 '='

binascii.hexlify(b'flag')             # b'666c6167'
binascii.unhexlify('666c6167')        # b'flag'
struct.pack('<I', 0x41424344).hex()   # '44434241'  小端打包（二进制协议题）
struct.unpack('<I', b'ABCD')[0]       # 1145258561
  • hashlib 没有 MD5 的"爆破"能力，但小空间穷举直接用循环 + digest()。
  • 大文件摘要用 h = hashlib.sha256(); h.update(chunk); h.digest() 分块喂。

9. 命令行工具（一条命令顶一段代码）

# --- OpenSSL（本机 3.5.5，原生支持国密）---
openssl dgst -sm3 file                    # SM3 摘要
openssl enc -sm4-cbc -K <32位hex> -iv <32位hex> -in f -out f.enc    # SM4-CBC 加密
openssl enc -sm4-cbc -d -K ... -iv ... -in f.enc                    # 解密
openssl genrsa -out k.pem 1024            # 生成 RSA 私钥
openssl rsa -in k.pem -text -noout        # ★ 打印 n/e/d/p/q（RSA 题第一步）
openssl rsa -in k.pem -pubout             # 导出公钥 PEM
openssl base64 / echo -n flag | openssl base64
openssl enc -aes-128-cbc -in f -out f.enc -K ... -iv ...   # 对称加解密

# --- GnuPG（本机 2.4.9）---
gpg --list-keys / gpg -d file.gpg / gpg --verify sig file

注意：openssl enc 的 -K（大写）是十六进制密钥，-k（小写）是口令派生，别混。
OpenSSL 的 SM2 密文是 DER 编码，对应 gmssl 的 asn1=True。

11. 踩坑清单（全部本机实测）

# 坑 正确做法
1 (a**b) % m 慢 1000+ 倍且会卡死 pow(a, b, m)
2 str()/int() 转换超 4300 位报 ValueError sys.set_int_max_str_digits(100000)；或改用 hex()/to_bytes()
3 RSA.generate(512) 报错 最小 1024 位
4 ECB/CBC/CTR 构造参数不同，IV 必须显式给 ECB 无 IV；CBC/OFB 传 16 字节 iv；CTR 传 nonce=
5 AES 解密后尾部 \x04\x04\x04\x04 加密 pad、解密 unpad
6 pkcs1_15.verify() 失败不返回 False 而是抛异常 用 try/except，成功返回 None
7 sympy.crt 参数传反不报错但结果错 crt(m_list, v_list)，模数在前
8 sympy.discrete_log 参数语义搞混 → Log does not exist discrete_log(n, target, base)
9 gmssl SM3 传 bytes 报错 sm3_hash(func.bytes_to_list(data))，返回 hex 字符串
10 gmssl SM2 的 mode 注释与实现不符 默认 mode=0 = C1C2C3；以实测为准，加解密两侧统一
11 拿 OpenSSL 的 SM2 密文直接喂 gmssl 解不开 那是 DER 格式 → CryptSM2(..., asn1=True)
12 SM4 输出比输入长一倍 它默认 PKCS7 填充，正常现象
13 SM2 k 重用照抄 ECDSA 公式 → 私钥错 SM2 用 d = t/(1−t)
14 DES3.new(b'0'*24, ...) 报 ValueError 三段密钥不能相同（退化 key）
15 hashlib 找 sm3 属性 本机没有，用 gmssl 或 openssl CLI
16 gmpy2.mpz() 到处乱套以为会快 只在大数模幂/开方上有 ~9× 收益；普通循环无差别
17 老笔记里的 ~/\python.exe 已卸载，用 py 或上面的 Sage 命令
18 Sage 脚本用 py 跑，报没有 sage.all 必须用 runtime\bin\bash.exe --login -c ".../sage -c '...'"
