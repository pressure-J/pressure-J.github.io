LFSR线性反馈移位寄存器-状态恢复

密码学 2026-09-08 3233 字 约 9 分钟
crypto

一、流密码是什么（先建立直觉）

对称密码分两大类：

类型 原理 代表
分组密码 明文按块(如16字节)整体加密 AES / DES
流密码 生成一串伪随机密钥流，与明文逐位异或 RC4、LFSR 系(A5/1、Trivium)

流密码的核心是一个密钥流生成器：输入密钥(种子)，输出无限长的伪随机比特流。加密/解密都只是"把明文和密钥流逐位异或"，密钥流一样就互为逆。

CTF 里常见的流密码题：给你生成器代码 + 生成的密钥流文件(如 key)，让你反推种子(常就是 flag)。

二、LFSR 是怎么当"流密码"用的

**LFSR（线性反馈移位寄存器）**是最简单的密钥流生成器：

寄存器 R (32位)  ← 初值 = 种子(flag)
       │
       │  ① 整体左移一位
       ▼
   最高位移出丢弃 ← 用 mask 抽头位做异或 ──→ 反馈位 lastbit
       │                                         │
       └── 反馈位补进最低位 ────────────────────────┘
                      ↓
               lastbit 同时作为本步输出(密钥流1bit)

对应代码：

def lfsr(R, mask):
    output = (R << 1) & 0xffffffff   # ① 左移，最高位顶掉
    lastbit = parity(R & mask)       # ② mask 选中的位全部异或 → 反馈位
    output ^= lastbit                # ③ 反馈位补到最低位
    return output, lastbit
  • mask（抽头多项式）决定"用哪些位做异或"，是 LFSR 的结构参数（本题 0b101001...）
  • 每跑一步输出 1 bit；脚本每 8 步打包成 1 字节写入 key → 100 字节 = 800 bit 密钥流

三、为什么能破解：LFSR 是"线性+无混淆"的

这是 LFSR 的核心弱点，也是所有攻击的入口：

  1. 线性：每个输出位都是寄存器若干位的异或组合，没有非线性运算（无混淆），结构完全可逆
  2. 输出泄露内部状态：每步输出的 lastbit 恰好就是将要移入寄存器的那一位

由 2 直接得出关键洞察——输出的位会一路滚进寄存器：

第0步输出 b0 → 移入，寄存器=[b0, ...]
第1步输出 b1 → 移入，寄存器=[b0, b1, ...]
...
第31步后     → 寄存器=[b0, b1, ..., b31]  (32位正好装满)

所以：连续 32 个输出位拼起来 = 32 步之后的寄存器状态，无需知道任何中间过程。
$$R_{32} = b_0 b_1 \cdots b_{31}$$

拿到 R_32 后，因为整个变换是线性的、可逆的，逆推 32 步就回到初始状态 R_0（即 flag）。

四、逆推原理（解密核心）

已知 R_next 还原 R，抓住三点：

  • 反馈位就在最低位：b = R_next & 1
  • R_next >> 1 = 原 R 的低 31 位（最高位被移丢，先补 0 占位）→ low
  • 被移丢的最高位 top 是唯一未知量。用反馈关系约束它：
    $$b = top \oplus parity(low \& mask) \;\Rightarrow\; top = b \oplus parity(low \& mask)$$
    （必须 mask 最高位 = 1，否则 b 里不含 top 的信息，解不出）
def rev(R_next, mask):
    lastbit = R_next & 1
    low = R_next >> 1
    top = lastbit ^ parity(low & mask)
    return low | (top << 31)

重复 32 次 → R_0。

现实中不这么手动逆推也行：LFSR 是线性系统，输出位与初态的关系可用线性方程组(GF(2))表达，或直接用 Berlekamp-Massey 算法求最短 LFSR。CTF 里"给脚本+输出"的题，用上面的逆推最直观。

题型识别（一眼看出）

题目给一段 LFSR 加密脚本 + 一个输出文件，脚本形如：

def lfsr(R, mask):
    output = (R << 1) & 0xffffffff
    i = R & mask
    lastbit = 0
    while i:
        lastbit ^= (i & 1)   # 抽头异或
        i >>= 1
    output ^= lastbit
    return output, lastbit

for i in range(100):          # 每 8 步打包成一个字节
    tmp = 0
    for j in range(8):
        R, out = lfsr(R, mask)
        tmp = (tmp << 1) ^ out
    f.write(chr(tmp))

本质：已知 mask（抽头）和输出位流，求初始状态 R（R 通常就是 flag 的 hex，如 flag{xxxxxxxx}）。

五、攻击条件

  • 已知 mask（反馈抽头多项式）
  • 已知足够长的输出位流（≥ 寄存器位宽即可，本题 32 位）
  • 寄存器位宽已知（本题 flag hex 8 位 → 32 bit）

原理推导（承接上文"四、逆推原理"的完整推导）

核心洞察：每步输出的 lastbit 正是移入寄存器的新位。设输出位序列 b0, b1, b2, ...（bi 是第 i 步的 lastbit）。

寄存器递推：R_{t+1} = (R_t << 1) | b_t，展开：
$$R_{32} = b_0 b_1 \cdots b_{31}$$

即连续 N 位输出拼起来，就是 N 步之后的寄存器状态（本题 N=32）。

逆推：已知 R_next，要还原 R：
- 反馈位 b = R_next & 1
- low = R_next >> 1（= R 的低 31 位，最高位补 0）
- 被移出的最高位 top 满足 b = top XOR parity(low & mask)
→ top = b XOR parity(low & mask)（要求 mask 最高位 = 1，否则不可唯一恢复）
- R = low | (top << 31)

逆推 32 步即得初始状态 R0。

六、解题步骤

  1. 字节流 → 位流：每字节 MSB 优先（(byte >> j) & 1, j=7..0）
  2. 取前 32 位拼成 R32（第一位为 MSB）
  3. 逆推 32 步 → R0
  4. 验证：用 R0 正推，应复现整个 key 文件
  5. flag = "flag{" + format(R0, '08x') + "}"

七、解题脚本

（该脚本已随旧目录移除。同类问题的通用做法见 ~/tools\CTF工具箱\crypto\23-FCSR线性化攻击.py 的事件扫描框架，以及本目录 FCSR线性化攻击-F-FCSR状态恢复.md）

def rev(R_next, mask):
    lastbit = R_next & 1
    low = R_next >> 1
    top = lastbit ^ parity(low & mask)
    return low | (top << (mask.bit_length()-1))
# 取前 N 位 -> 逆推 N 步 -> R0

八、易错点

  1. 位序：打包时 tmp = (tmp << 1) ^ out，所以每字节是 MSB 优先，读位流别搞反
  2. mask 最高位必须为 1：否则逆推时被移出的最高位无法确定（本题 mask 最高位恰好是 1）
  3. 逆推步数 = 寄存器位宽：多推少推都得不到初态
  4. 一定正推验证：这是唯一能确认 R0 正确的办法
  5. 更通用的做法：若 mask 未知/结构复杂，可用 Berlekamp-Massey 算法求最短 LFSR；本题结构简单，直接逆推即可

九、实战记录

  • 来源：[CISCN 2018] oldstreamgame
  • mask = 0b10100100000010000000100010010100，32 位寄存器
  • key 100 字节 → 位流前 32 位 = 0x20fdeef8（32 步后状态）
  • 逆推 32 步 → R0 = 0x926201d7
  • 正推复现 key：True
  • 结果：flag{926201d7}
