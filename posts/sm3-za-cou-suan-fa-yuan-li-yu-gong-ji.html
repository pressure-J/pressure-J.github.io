SM3-杂凑算法原理与攻击

密码学 2026-10-14 5587 字 约 15 分钟
cryptohashsm3

国密密码杂凑算法，标准号 GM/T 0004（GB/T 32905）。输入任意长度，输出固定 256 bit 摘要（8 个 32 位字）。设计对标 SHA-256，同为 Merkle–Damgård 结构。

2. 算法原理

2.1 整体流程

消息 M → 填充到 512 bit 倍数 → 分块 B₀ B₁ ... Bₙ₋₁
→ V₀ = IV
→ for i: V_{i+1} = CF(V_i, B_i)
→ 输出 V_n（256 bit）

  • 分组 512 bit，摘要 256 bit，压缩函数 64 轮。
  • CF 是压缩函数，可看作分组密码的 Davies–Meyer 模式（$V_{i+1} = E_{B_i}(V_i) \oplus V_i$）。

2.2 初始向量 IV

SM3 的 IV 是独立设计的，与 SHA-256 完全不同（这点常被误传）：

值
SM3 IV 7380166f 4914b2b9 172442d7 da8a0600 a96f30bc 163138aa e38dee4d b0fb0e4e
SHA-256 IV 6a09e667 bb67ae85 3c6ef372 a54ff53a 510e527f 9b05688c 1f83d9ab 5be0cd19

实测确认两者无一字相同——SM3 是独立设计，不是改自 SHA-256。

2.3 消息填充（关键：长度扩展攻击的基础）

记消息长度为 $l$ 比特，填充规则：

  1. 追加一个 0x80（比特 1 后跟 0）；
  2. 补 0x00 直到长度 $\equiv 448 \pmod{512}$；
  3. 追加 8 字节大端的原始长度 $l$（以 bit 计）。

注意长度是 bit 不是 byte——这是实现时最容易错的点。填充后总长是 512 的倍数。

2.4 消息扩展

每个 512 bit 分组 $B$ 拆成 16 个 32 位字 $W_0..W_{15}$，扩展成 68 个 $W$：

$$W_j = P_1(W_{j-16} \oplus W_{j-9} \oplus (W_{j-3} \lll 15)) \oplus (W_{j-13} \lll 7) \oplus W_{j-6}, \quad j = 16..67$$

再生成 64 个 $W'$：

$$W'j = W_j \oplus W, \quad j = 0..63$$

2.5 压缩函数（64 轮）

状态 $V = (A,B,C,D,E,F,G,H)$，每轮：

$$
\begin{aligned}
SS_1 &= ((A \lll 12) + E + (T_j \lll j)) \lll 7 \
SS_2 &= SS_1 \oplus (A \lll 12) \
TT_1 &= FF_j(A,B,C) + D + SS_2 + W'_j \
TT_2 &= GG_j(E,F,G) + H + SS_1 + W_j
\end{aligned}
$$

然后整体左移一位：

$$D \leftarrow C,\ C \leftarrow B \lll 9,\ B \leftarrow A,\ A \leftarrow TT_1$$
$$H \leftarrow G,\ G \leftarrow F \lll 19,\ F \leftarrow E,\ E \leftarrow P_0(TT_2)$$

布尔函数（前 16 轮与后 48 轮不同，实测源码确认）：

轮 $FF_j$ $GG_j$
$0\le j<16$ $X \oplus Y \oplus Z$ $X \oplus Y \oplus Z$
$16\le j<64$ $(X \wedge Y) \vee (X \wedge Z) \vee (Y \wedge Z)$ $(X \wedge Y) \vee (\neg X \wedge Z)$

置换函数（实测确认移位量）：

$$P_0(X) = X \oplus (X \lll 9) \oplus (X \lll 17)$$
$$P_1(X) = X \oplus (X \lll 15) \oplus (X \lll 23)$$

轮常数 $T_j$（实测只有两个取值）：

轮 $T_j$
$0\le j<16$ 0x79cc4519
$16\le j<64$ 0x7a879d8a

3. 常见攻击

3.1 攻击一：长度扩展攻击（CTF 高频，必会）

根因：MD 结构下摘要 = 最后一次压缩后的内部状态 $V$，原始长度只参与了填充、没有在最后混回输出。所以拿到 digest 就等于拿到了内部状态。

攻击场景：

服务端计算: digest = SM3(SECRET || user_data) # SECRET 未知
攻击者目标: 伪造 SM3(SECRET || user_data || padding || append) 的合法摘要

攻击步骤：

  1. 把已知 digest 的 8 个字直接当作内部状态 $V$；
  2. 从该状态继续向后压缩 append + 新填充；
  3. 算出新摘要，连同 user_data || padding || append 一起提交，服务端会接受。

三个必踩的坑：

坑 说明
填充分两个位置 glue = pad(secret_len + len(orig_data)) 把原消息补到分组边界，它已体现在已知 digest 里，不要重复压缩；从 state 出发只需压缩 append + tail，其中 tail = pad(新总长度)
SECRET 长度必须对 长度错则填充全错、摘要全错。不知道就爆破 0..63，靠服务端是否接受判定
长度以 bit 计 填充尾部 8 字节是 原长度 × 8 的大端表示

实测（SM3-长度扩展攻击-solve.py）：

项 值
服务端密钥 b's3cr3t_k3y_16byte'（长度 17，攻击者不可见）
原始数据 user=guest&role=guest
原始摘要 8f25a69ec69abd2414491aef1b61e996e11385f316ded584e6544964ead0a7fa
爆破长度 0..63 命中 L = 17
伪造摘要 773c27addcefd07d879e2592b5a7f08e10936a85e09b1585d0ab9f159f40e0b1

反例：猜长度 0/4/8/12/20 全部被拒绝，只有真实长度 17 通过。

3.2 攻击二：原像攻击与哈希爆破

  • 全 64 轮 SM3 原像攻击复杂度 $2^{256}$，不可行。
  • 但明文空间小时（弱口令、短数字、残缺明文），直接字典/暴力最有效。
  • 工具：hashcat、john；CTF 残缺明文（? 占位）用 ..\01-基础密码\hash-brute-force-solve.py（方法见同目录 ..\01-基础密码\哈希明文爆破.md）。

3.3 攻击三：碰撞攻击（学术向）

公开最好的结果（截至权威汇总）：

攻击类型 目标 覆盖轮数 复杂度
碰撞 完整哈希 20 / 64 实用
自由起始碰撞 压缩函数 24 / 64 实用
原像 完整哈希 28 / 64 $2^{241.5}$
回旋镖区分器 压缩函数 37~38 / 64 $2^{125}$ ~ $2^{192}$

全 64 轮碰撞无可行攻击（Mendel 等人 2013 年只做到 20 轮）。MD-SHA 家族里 SM3 的抗碰撞轮数占比最低（31%），安全裕度优于 SHA-1。

CTF 不会考这个，但面试会问"SM3 安全吗"——答：全轮安全，缩减轮数有理论攻击。

3.4 攻击四：MD 结构固有弱点汇总

长度扩展攻击只是 MD 结构弱点之一：

  • 长度扩展（已述）；
  • 第二原像的 herding 攻击（对长消息可降复杂性）；
  • 多碰撞（Joux 攻击）—— 影响基于 MD 哈希的"concatenation"构造安全性。

防御：改用 SM3-HMAC（标准接口常量 SGD_SM3_HMAC = 0x00000008），或换 SHA-3 这类海绵结构（天然免疫长度扩展）。

3.5 攻击五：弱实现与自定义 IV

  • 题面若给出非标准 IV，务必核对——很多"看起来是 SM3"的题其实是自造的类 SM3。
  • 截断输出（取前 128 bit）会显著降低抗碰撞强度，可做生日攻击。
  • 单次调用处理多消息时复用状态（未重置 IV）→ 状态残留泄露。

4. 工具链

工具 用法
OpenSSL 3.5.5 echo -n abc \| openssl dgst -sm3（本机已实测）
Python gmssl sm3.sm3_hash(func.bytes_to_list(b'...'))
Python hashlib ⚠️ 标准库 3.x 不提供 SM3，别在这找
gmssl 底层函数 sm3_cf(v_i, b_i) 可直接调用压缩函数——做长度扩展攻击必须用它

gmssl 的坑（实测）：

  • sm3_hash(msg) 接收的是 list of int，不是 bytes。直接传 bytes 会出错，必须 func.bytes_to_list(b'...')。
  • sm3_cf(v_i, b_i) 是导出可用的，长度扩展攻击正是靠它从任意状态继续压缩。
  • sm3_kdf(z, klen) 是 SM2 加密用的 KDF（$KDF = SM3(Z | ct)$ 迭代，ct 从 1 递增），参数 z 是 hex 字符串的 bytes。

5. 面试速答卡

问：SM3 和 SHA-256 的本质区别？
答：同为 MD 结构、512 bit 分组、256 bit 输出、64 轮。IV 完全不同（SM3 独立设计）；压缩函数不同——SM3 消息扩展出 68 个 W + 64 个 W'（SHA-256 是 64 个 W）；轮常数 SM3 只有两个取值 0x79cc4519/0x7a879d8a（SHA-256 有 64 个不同常数）；布尔函数 16 轮切换（SHA-256 是 20 轮切换 Cha/ Maj）。安全性质等同。

问：SM3 有长度扩展攻击吗？为什么？
答：有。因为它是 MD 结构——摘要就是最后压缩后的内部状态，原始长度只进了填充没混回输出。所以拿到 digest = 拿到状态，可以继续往后压缩任意数据。

问：怎么防长度扩展攻击？
答：用 HMAC（HMAC(SECRET, msg)）代替 H(SECRET || msg)；或换 SHA-3 海绵结构。

问：SM3 的抗碰撞性怎么样？
答：全 64 轮无可行攻击；公开最好仅 20 轮碰撞、24 轮自由起始碰撞。MD-SHA 家族里安全裕度最好。

问：SM3 的 P0 和 P1 分别什么时候用？
答：$P_0$ 用于压缩函数中 $TT_2$ 的输出（$E \leftarrow P_0(TT_2)$）；$P_1$ 用于消息扩展生成 $W_j$。$P_0$ 移位 9/17，$P_1$ 移位 15/23。
