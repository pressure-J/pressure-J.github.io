Webshell 上传与加密隧道流量分析

应急响应2026-07-08

流量分析 WriteUp

题目信息

某日凌晨，某重点单位网络安全设备突然触发告警，检测到内网流量异常。安全团队紧急响应，发现一台核心服务器疑似被攻击者横向渗透，并通过加密隧道进行通信和数据传输。安全设备完整捕获了攻击过程的流量（文件：流量分析.pcapng）。

目标：找到攻击者添加的后门用户名称，flag 格式为 flag{后门用户名称}

攻击路径总览

攻击者 192.168.1.100
    │
    ├─ 步骤1: 端口扫描 (发现 192.168.1.200:8022)
    │
    ├─ 步骤2: Web路径探活 (扫描 php/aspx/jsp 等)
    │
    ├─ 步骤3: 上传 Webshell (upload.php → w.php)
    │
    ├─ 步骤4: 加载 PHP 后门框架 (Godzilla/冰蝎类)
    │
    ├─ 步骤5: 执行系统命令
    │   ├─ whoami
    │   ├─ net user            ← 查看现有用户
    │   ├─ net user hacker-gg /add  ← 创建后门用户
    │   ├─ netstat -an
    │   ├─ tasklist
    │   └─ back.exe            ← 启动加密隧道
    │
    └─ 步骤6: 加密隧道通信 (数据传输)

详细分析过程

1. 流量概览

使用 tshark 或 scapy 读取 pcapng 文件：

统计项 数值
总包数 2183
攻击者 IP 192.168.1.100
目标服务器 IP 192.168.1.200
目标服务端口 8022 (Apache/2.4.39 + PHP/7.3.4)

2. 发现扫描行为

攻击者 IP 192.168.1.100 对 192.168.1.200 进行了全端口扫描：

  • 扫描端口数：100+（端口 3306、445、3389、22、6379 等）
  • 主要通信集中在端口 8022
  • 端口扫描后，攻击者进行了 Web 路径探活，尝试了 .php、.aspx、.jsp、.gitignore 等常见路径

3. 定位 Webshell 上传

在 TCP Stream 中发现攻击者通过 /upload.php 上传了文件：

POST /upload.php HTTP/1.1
Host: 192.168.1.200:8022
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryte9SAVO9MO1ENwOe
Referer: http://192.168.1.98:8022/upload.php

上传的文件为 w.php，这是一个加密 Webshell：

<?php
@session_start();
@set_time_limit(0);
@error_reporting(0);
function encode($D,$K){
    for($i=0;$i<strlen($D);$i++) {
        $c = $K[$i+1&15];
        $D[$i] = $D[$i]^$c;
    }
    return $D;
}
$pass='gg';
$payloadName='payload';
$key='3c6e0b8a9c15224a';

Webshell 特征： - 密码：gg - 加密方式：XOR + Base64 双层加密 - XOR 密钥：3c6e0b8a9c15224a - 上传来源 IP：192.168.1.98（可能是攻击者的跳板机）

4. Webshell 通信分析

上传成功后，生成的 Webshell 路径为：

/uploads/php_68525da04b2c37.31016234.php

Webshell 通信数据流： 1. 首次请求：发送的 gg= 参数包含 PHP eval 框架代码（~40000 字符），存储在 Session 中 2. 后续请求：每次发送加密后的 methodName + 参数，服务端 eval 执行后返回 gzip 压缩结果

响应格式：

echo substr(md5($pass.$key),0,16);  // md5("gg3c6e0b8a9c15224a") 前16位 = "d5c17b7d4d3e3f71"
echo base64_encode(encode($data,$key));

5. 解密执行命令

使用 Python + Scapy 编写解密脚本，提取 gg= 参数并：

1. URL Decode
2. 修正 Base64 填充（%4 == 1 时截断）
3. Base64 解码
4. XOR 解密（key = "3c6e0b8a9c15224a", 从 key[1] 开始循环）
5. 前 2 字节为 0x1f8b 时，Gzip 解压

解密后的关键命令：

Stream 解密后命令 说明
61809 cmd /c "cd /d "E:/system/phpstudy_pro/WWW/uploads/"&whoami" 查看当前用户
61809 cmd /c "cd /d "E:/system/phpstudy_pro/WWW/uploads/"&net user" 列出系统用户
61870 cmd /c "cd /d "E:/system/phpstudy_pro/WWW/uploads/"&net user hacker-gg /add" 创建后门用户 ← 关键证据
61870 cmd /c "cd /d "E:/system/phpstudy_pro/WWW/uploads/"&net user" 再次列出用户（确认已创建）

62351 cmd /c "cd /d "E:\system\phpstudy_pro\WWW"&back.exe" 启动加密隧道程序

6. 加密隧道

攻击者在创建后门用户后，运行了 back.exe 程序，用于建立加密隧道进行后续的数据传输。TCP Stream 中出现大量 1460 字节的数据包（TCP MSS 最大分段），呈现加密流量的典型特征。

Flag

flag{hacker-gg}

总结

攻击阶段 技术手法 流量特征
信息收集 端口扫描 + Web路径探活 大量 SYN 包 + HTTP 404
初始入侵 上传 Webshell POST multipart/form-data
权限维持 创建后门用户 hacker-gg net user hacker-gg /add 命令
隧道通信 运行 back.exe 加密传输 大量 1460 字节 TCP 数据包

关键证据链：扫描 → 上传 ➔ 命令执行 ➔ 后门创建 ➔ 加密隧道，完整还原了攻击者的整个攻击路径。
