Windows 安全日志分析：RDP 暴力破解识别

应急响应2026-07-08

Windows 安全日志分析（RDP 暴力破解类题目）

一、题目特征

这类题目通常会提供 Windows 安全日志（Security Log）文件，格式为 XML，需要从中分析出：

要找的信息 说明
攻击源 IP 发起暴力破解的 IP 地址
被攻破的账号 成功登录的账户名
攻击时间段 暴力破解的起止时间
攻击手法 是否为 RDP、SMB 等

常见 flag 格式：flag{攻击IP_用户名} 或 flag{IP_用户}

二、Windows 安全日志关键事件 ID

EventID 含义 用途
4625 登录失败 找暴力破解记录（重点是 LogonType=10）
4624 登录成功 找被攻破的账号（重点是 LogonType=10）
4634 登出 辅助确认登录会话时长
4648 使用显式凭据登录 可能涉及横向移动
4672 分配特殊权限 管理员权限登录时会触发

LogonType 速查表

LogonType 名称 说明
2 Interactive 本地控制台登录
3 Network 网络访问（如 IPC 连接）
4 Batch 批处理任务
5 Service 服务启动
7 Unlock 屏幕解锁
8 NetworkCleartext 明文网络登录（如 IIS）
9 NewCredentials 使用不同的凭证
10 RemoteInteractive 远程桌面（RDP）—— 重点关注

三、分析思路（通用方法论）

Step 1: 了解日志结构
    └─ 确认文件格式（XML），找到 Events/Event 节点结构

Step 2: 统计暴力破解概况
    └─ 搜索 EventID=4625（登录失败）
    └─ 从 LogonType 识别 RDP（=10）
    └─ 从 SourceNetworkAddress 提取攻击源 IP
    └─ 从 TargetUserName 提取被攻击账号

Step 3: 定位攻击源 IP
    └─ 统计各 IP 的失败次数，找出发起暴力破解的攻击源
    └─ 攻击源特征：失败次数远超其他 IP
    └─ 其他 IP 少量失败（1-5次）通常是正常用户输错密码

Step 4: 查找成功登录
    └─ 搜索 EventID=4624（登录成功）+ LogonType=10
    └─ 提取 SourceNetworkAddress 和 TargetUserName
    └─ 确认攻击源 IP 是否有成功登录记录

Step 5: 关联确认
    └─ 攻击源 IP 是否在短时间内多次失败后成功？
    └─ 成功登录的账号是否被暴力破解？

四、使用 Excel 分析 XML 文件

4.1 将 XML 导入 Excel

方法 A：直接打开（推荐）

  1. 打开 Excel → 文件 → 打开 → 浏览
  2. 文件类型选择 "所有文件(.*)"
  3. 选中 Security_log.xml → 打开
  4. 在弹出的对话框中选择 "作为 XML 表"
  5. Excel 会自动生成表格结构

方法 B：使用 Power Query（Excel 2016+）

  1. Excel → 数据 → 获取数据 → 从文件 → 从 XML
  2. 选择 Security_log.xml
  3. 在 Power Query 编辑器中选择需要展开的字段
  4. 加载到工作表

4.2 Excel 中的关键操作

① 筛选 RDP 登录失败记录（4625）

  • 找到 System_EventID 列（或类似名称）
  • 下拉筛选 → 只勾选 4625
  • 找到 EventData_Data_LogonType 列 → 筛选 10

② 筛选 RDP 登录成功记录（4624）

  • 筛选 4624 + LogonType=10
  • 查看 SourceNetworkAddress 列（源 IP）
  • 查看 TargetUserName 列（目标账号）

③ 数据透视表统计

  • 选中数据区域 → 插入 → 数据透视表
  • 行：SourceNetworkAddress（源 IP）
  • 值：EventRecordID（计数）
  • 按计数降序排列 → 次数最多的就是攻击源

五、XML 结构详解（方便理解 Excel 列名）

Windows 安全日志 XML 的结构如下：

<Events>
  <Event>
    <System>
      <EventID>4625</EventID>                    <!-- 事件ID -->
      <TimeCreated SystemTime="..."/>              <!-- 时间 -->
    </System>
    <EventData>
      <Data Name="LogonType">10</Data>            <!-- 登录类型 -->
      <Data Name="TargetUserName">administrator</Data>  <!-- 目标账号 -->
      <Data Name="SourceNetworkAddress">192.168.10.3</Data>  <!-- 源IP -->
      <Data Name="FailureReason">未知用户名或错误密码</Data>  <!-- 失败原因 -->
    </EventData>
  </Event>
</Events>

Excel 解析时，列名通常由 <Data Name=""> 中的值生成：

XML 路径 Excel 列名示例
System/EventID System_EventID
System/TimeCreated System_TimeCreated
EventData/Data[@Name='LogonType'] EventData_Data_LogonType
EventData/Data[@Name='TargetUserName'] EventData_Data_TargetUserName
EventData/Data[@Name='SourceNetworkAddress'] EventData_Data_SourceNetworkAddress

六、实际案例复盘

以本题 Security_log.xml 为例：

步骤 操作 结果
1 统计 4625 事件 177 条失败记录
2 过滤 LogonType=10 全部为 RDP 攻击
3 按 IP 分组统计 192.168.10.3: 152 次（攻击源）
4 其余 IP 失败次数 1-5 次（正常用户）
5 查找 4624 + LogonType=10 192.168.10.3 → administrator 成功登录

Flag：flag{192.168.10.3_administrator}

七、使用 tshark/cmd 快速分析（无 GUI 环境）

如果无法使用 Excel，也可以用命令行快速分析：

统计各 IP 失败次数：

findstr /C:"4625" Security_log.xml > failed.txt
findstr /C:"192.168" failed.txt | find /C "IP地址"

PowerShell 统计：

[xml]$xml = Get-Content "Security_log.xml"
$xml.Events.Event | Where-Object { 
    $_.System.EventID -eq 4625 -and 
    ($_.EventData.Data | Where-Object { $_.Name -eq 'LogonType' }).'#text' -eq 10
} | ForEach-Object {
    ($_.EventData.Data | Where-Object { $_.Name -eq 'SourceNetworkAddress' }).'#text'
} | Group-Object | Sort-Object Count -Descending

八、Excel 分析总结

优点 缺点
可视化筛选，操作直观 XML 嵌套深时列名可能混乱
数据透视表快速统计 大文件可能卡顿
无需编写代码 某些 Data 字段可能丢失
适合非技术人员 需要手动过滤无关数据

推荐用法：Excel 做快速筛查 → Python/脚本做精确统计 → 交叉验证结果
