Shiro反序列化RCE流量分析WriteUp

应急响应 2026-07-10 5006 字 约 13 分钟
应急响应流量分析Shiro反序列化WriteUp

题目信息

企业服务器被入侵，安全团队抓取了攻击流量。开发人员确认系统使用了 Shiro 框架的默认密钥 90F1FE6C8C64E43D9D799888C5C69A68。分析攻击流量包，确认攻击者攻击时用的恶意类的名称。

flag 格式: flag{恶意类名称}

日志概况

统计项 数值
流量文件 娴侀噺.pcapng (167 KB)
目标服务器 192.168.103.253:8089（Shiro Web 应用）
攻击者 IP 192.168.103.251
攻击类型 Shiro RememberMe 反序列化 RCE（CVE-2016-4437）
最终答案 flag{Test105692713192100}

攻击路径总览

Phase 1: 指纹探测 (0s)
  └─ 发送 rememberMe=1 → 确认 Shiro 框架
  └─ 服务器返回 deleteMe → 验证成功

Phase 2: 反序列化攻击 (4.7s)
  └─ 发送恶意 rememberMe Cookie（AES 加密的 Java 序列化 payload）
  └─ Shiro 使用默认密钥解密 → 反序列化 → 触发 RCE

Phase 3: 命令执行 (16.2s ~ 45.1s)
  └─ POST / 提交表单 → 执行系统命令
  └─ 通过反序列化通道持续控制服务器

详细分析过程

Phase 1：Shiro 框架指纹探测

在 Wireshark 中过滤 HTTP 请求：

http.request

攻击者 192.168.103.251 发第一个请求：

GET / HTTP/1.1
Cookie: rememberMe=1

服务器返回 302，响应头包含关键特征：

HTTP/1.1 302
Set-Cookie: rememberMe=deleteMe; Path=/; Max-Age=0; ...
Set-Cookie: JSESSIONID=DE74E79A10104F065CC7D04AE9407800; Path=/; HttpOnly

Shiro 指纹特征：当 rememberMe Cookie 值无法解密时，Shiro 会自动设置 rememberMe=deleteMe。这是 Apache Shiro 框架的独有特征。

Wireshark 过滤方法：

# 过滤 Shiro 指纹
http.response && http contains "rememberMe=deleteMe"

Phase 2：构造恶意 RememberMe Cookie

确认 Shiro 框架后，攻击者发送带恶意序列化 payload 的 Cookie：

GET / HTTP/1.1
Cookie: rememberMe=[超长 Base64 编码字符串]

定位方法：在 Wireshark 中找到 HTTP 请求中 Cookie 值特别长的几个请求（帧 115-120、129-136 等），它们的 rememberMe Cookie 值超过 900 字节。

Phase 3：命令执行

在 26.7s 和 45.1s，攻击者通过 POST / 发送表单数据，通过反序列化通道持续执行命令。

核心：解密 RememberMe Cookie 提取恶意类名

本题最关键的一步是 解密 rememberMe Cookie，提取其中的 Java 序列化数据，找到攻击者嵌入的恶意类名。

加密原理

Shiro 的 RememberMe 功能使用 AES-CBC 加密：

明文 (Java 序列化数据)
  → AES/CBC/PKCS5Padding 加密
  → 将 IV(16字节) + 密文 拼接
  → Base64 编码
  → 放入 Cookie: rememberMe=<Base64>

Cookie 结构：

Cookie: rememberMe = Base64( IV(16字节) || AES-密文 )
                     ├───── 前32位十六进制 = IV ─────┤

解密步骤

1. 从 Wireshark 提取 Cookie 值

定位到帧 119（或 125、133），查看 HTTP 请求的 Cookie 值。

Wireshark 操作：
1. 找到帧 119 → Follow HTTP Stream
2. 复制 Cookie: rememberMe= 后面的完整 Base64 字符串

2. 编写 Python 解密脚本

使用 Shiro 默认密钥进行 AES-CBC 解密：

import base64
from Crypto.Cipher import AES

KEY_HEX = "90F1FE6C8C64E43D9D799888C5C69A68"
key = bytes.fromhex(KEY_HEX)

# 从 Wireshark 提取的 Base64 Cookie 值
b64_data = "BSTAxygllliVm7k1w5tK4HPI8ieV4JZvvpmEym8z+aFnLG+1W6v6HBhMxC7zQiyBK+..."

raw = base64.b64decode(b64_data)
iv = raw[:16]           # 前16字节 = IV
ciphertext = raw[16:]   # 后续 = 密文

cipher = AES.new(key, AES.MODE_CBC, iv)
decrypted = cipher.decrypt(ciphertext)

# PKCS7 去填充
pad_len = decrypted[-1]
decrypted = decrypted[:-pad_len]

print(decrypted.hex().upper())

组件 类名 说明

第二段 payload（帧 150）

第二段 payload 包含不同的字节码，类名为 Test105714876940900，包含 getFV、getClass 等方法，疑似用于反射获取 Shiro 密钥或其他敏感信息。

Gadget Chain 分析

本题攻击者使用 CommonsBeanutils1 链（ysoserial 项目中的标准链）：

PriorityQueue
  └─ siftDownUsingComparator()
      └─ BeanComparator.compare()
          └─ PropertyUtils.getProperty()
              └─ TemplatesImpl.getOutputProperties()
                  └─ TemplatesImpl.newTransformer()
                      └─ TemplatesImpl.getTransletInstance()
                          └─ ClassLoader.defineClass()
                              └─ Test105692713192100.<init>()
                                  └─ Runtime.exec("cmd /c echo ...")

注意：CommonsBeanutils1 是 ysoserial 的 gadget chain 名称，不是本题要求的"恶意类的名称"。恶意类的名称是字节码中定义的 Test105692713192100。

在 Wireshark 中定位 Shiro 攻击的方法

方法 1：搜索 Shiro 指纹
  http.response && http contains "rememberMe=deleteMe"

方法 2：筛选超长 Cookie 请求
  http.request.http.Content-Length > 500 && http.request.uri == "/"

方法 3：Follow TCP Stream 看完整内容
  找到可疑请求 → 右键 → Follow → TCP Stream

Shiro 漏洞流量特征总结

特征 说明
Set-Cookie: rememberMe=deleteMe Shiro 框架指纹，响应头中出现即确认 Shiro
Cookie 值特别长 正常 rememberMe=1，攻击时可达数百至数千字节
Cookie 值为 Base64 乱码 解码后为 AES 加密的 Java 序列化数据
多次请求 + 302 跳转 每次攻击会先发 GET / 触发反序列化，再跳转到 /login

防御建议

  1. 升级 Shiro 版本：1.2.5 以下版本存在 CVE-2016-4437，升级到 1.2.5+
  2. 修改默认密钥：在 shiro.ini 或 Spring 配置中自定义 securityManager.rememberMeManager.cipherKey
  3. WAF 规则：拦截过长的 rememberMe Cookie 值
  4. 出站流量监控：关注异常的 DNS 查询（Shiro 常配合 DNSLog 使用）
  5. 最小化 RememberMe 功能：非必要场景禁用 RememberMe
